# Internationalized routing

volt serves one app in several locales from locale-prefixed URLs, like the Next.js Pages Router `i18n` config. It works with both the App Router and the Pages Router.

```toml
# volt.toml
[i18n]
locales = ["en", "de", "pt-BR"]
default_locale = "en"             # first locale when omitted
locale_detection = true           # redirect `/` to the visitor's locale
```

| URL | Locale | Route |
| --- | --- | --- |
| `/about` | `en` | `/about` |
| `/de/about` | `de` | `/about` |
| `/pt-BR` | `pt-BR` | `/` |
| `/en/about` | redirects with 308 to `/about` | |

The default locale is never prefixed. The server strips the prefix before matching routes, so one `app/about/page.tsx` (or `pages/about.tsx`) answers every locale. Locale prefixes match case-insensitively and redirect to the configured spelling (`/DE/about` to `/de/about`). Locale codes may contain letters, digits and `-`.

Without an `[i18n]` table nothing changes: there are no prefixes, and the locale reported everywhere is `[site] language`.

## Reading the locale

In React, `useLocale()` from `volt-rs/navigation` returns the active locale; `useI18n()` adds the configured list:

```tsx
import { useI18n, useLocale } from "volt-rs/navigation";

export default function RootLayout({ children }: LayoutProps) {
  return (
    <html lang={useLocale()}>
      <body>{children}</body>
    </html>
  );
}

function LocaleSwitcher() {
  const { locale, locales, defaultLocale } = useI18n();
  // ...
}
```

`usePathname()` returns the path without the locale prefix (`/about` on `/de/about`).

In Rust, loaders, actions and API handlers read `ctx.locale()`; `ctx.locales()` lists the configured locales:

```rust
#[loader("/about")]
async fn about(ctx: Ctx) -> Result<About> {
    Ok(About { greeting: translate(ctx.locale(), "greeting") })
}
```

Loaders and middleware see the locale of the page URL. Actions called from the client see the locale of the page that called them (the client sends it in an `x-volt-locale` header; forms posted without JavaScript use the referring page). API routes are not localized and get the default locale unless they read the request themselves.

## Links and navigation

Write hrefs without a locale prefix. `<Link>` and `useRouter()` keep the current locale:

```tsx
<Link href="/about">About</Link>                    {/* /de/about on a German page */}
<Link href="/about" locale="de">Deutsch</Link>     {/* always /de/about */}
<Link href="/about" locale="en">English</Link>     {/* /about */}
<Link href="/de/about" locale={false}>Raw</Link>   {/* href used as given */}

router.push("/about", { locale: "de" });
router.prefetch("/about", { locale: "de" });
```

An href that already starts with a locale is not prefixed again. With an explicit `locale`, an existing prefix is replaced. A language switcher is `<Link href={usePathname()} locale={other}>`.

Following a link or `router.push` with an explicit `locale` stores the choice in the `VOLT_LOCALE` cookie (one year), so locale detection respects it on the next visit to `/`.

Redirects keep the locale: `redirect("/login")` from a loader, an action or `redirect()` in a component of a German page goes to `/de/login`. Targets that already carry a locale prefix and external URLs are left alone.

## Locale detection

With `locale_detection = true` (the default), a `GET` of the unprefixed root `/` picks the visitor's preferred locale and answers `307` to `/<locale>` when it is not the default one:

1. the `VOLT_LOCALE` or `NEXT_LOCALE` cookie, when it names a configured locale;
2. otherwise the best match for `Accept-Language`, honoring `q` weights. Exact tags win; otherwise a shared primary language matches (`de-AT` picks `de`, `pt` picks `pt-BR`).

Only `/` detects; every other URL already names its locale. The root carries `Vary: Accept-Language, Cookie` so shared caches keep the variants apart. Set `locale_detection = false` to always serve the default locale at `/`.

## Pages Router

`useRouter()` from `next/router` (and the `Router` singleton) fill `locale`, `locales` and `defaultLocale`. `getServerSideProps` and `getStaticProps` receive `locale`, `locales` and `defaultLocale` in their context, `getStaticPaths` receives `locales` and `defaultLocale`, and `_document`'s `getInitialProps` context carries them too. `<Html>` from `next/document` sets `lang` to the active locale unless you pass one. `router.push(url, as, { locale: "de" })` switches locales.

Without `[i18n]` these fields are `undefined`, as in Next.js.

## SEO

When `[i18n]` is configured, every page renders `<link rel="alternate" hreflang>` for each locale plus `x-default` (the default locale URL), as absolute URLs on `[site] url`. `alternates.languages` from `metadata` is merged in and wins for the same language. Not-found and error pages get none.

`sitemap.xml` lists every page once per locale, each `<url>` with `xhtml:link` alternates for all locales and `x-default`. Entries from `#[sitemap]` providers are expanded the same way when they are paths without a locale prefix; absolute URLs and paths that already name a locale are listed as they are. `llms.txt` lists every locale variant.

## Prerendering and caching

Static routes and `generateStaticParams` / `getStaticPaths` paths are prerendered once per locale (`/blog/hello` and `/de/blog/hello`). The page cache keeps one entry per locale, and `revalidate_path("/blog/hello")` purges all of them. On the client, revalidation hints match routes without their prefix.

`volt export` writes every locale variant. Locale detection needs the server, so on a static host `/` always shows the default locale.

## Not supported

- Locale domains (`domains` in Next.js) are not implemented: locales are always path prefixes.
- API routes, `public/` files, `robots.txt`, `sitemap.xml` and `llms.txt` are not served under a locale prefix.
- Translations themselves are up to you: load messages in a loader keyed by `ctx.locale()`, or bundle them and pick by `useLocale()`.
